## Decision and remaining gates

A complete Cargo target/build snapshot paired with an authenticated workspace source projection is a reasonable small GitHub-only candidate. A target-only archive cannot establish the requested zero unchanged-dependency compiler work on a fresh checkout: Cargo uses source mtimes for path/workspace packages, and build-script inputs have additional mtime/environment semantics. The projection is therefore necessary state, not an optional speed improvement. Preserve complete real Cargo target and build directories; do not filter guessed internal fingerprints or fabricate dependency-only MBX exports. [Cargo fingerprinting](https://github.com/rust-lang/cargo/blob/5f94df4789f005f9a352888e8355ffc645b7ed0e/src/compiler/fingerprint/mod.rs), [build cache](https://github.com/rust-lang/cargo/blob/5f94df4789f005f9a352888e8355ffc645b7ed0e/doc/book/src/reference/build-cache.md).

The architecture is selected; its performance and capacity acceptance remain unproved. In particular, no current evidence proves the complete snapshots, tools, sources, all other existing families, and replacement overlap fit **10,000,000,000 stored bytes**. Current 4.0/5.2 GiB seed logs describe rejected raw MBX exports, not the compressed size of this proposed state. Live cache inventory was inaccessible through the current connector. Do not translate a successful action step, a restore hit, an empty MBX miss counter, or a lower job count into acceptance.

### One compiler routing policy

Keep each declared direct-Cargo or MBX/Mise command. Do not shadow Mise's Cargo command with a different binary to obtain easier measurements. Configure a stable owned **non-MBX RUSTC_WRAPPER observation adapter** through the generated/owned execution context before invoking the unchanged command. MBX 1.27 explicitly preserves an existing wrapper as MBX_PREVIOUS_RUSTC_WRAPPER and defers to it; run_rustc_shim skips its cache path and run_transparent_rustc passes the compiler and arguments to that wrapper. This uses supported upstream behavior and permits complete Cargo state to be the sole persistent compiled-state engine. It deliberately disables MBX compiler result caching for these observed commands, without replacing the declared driver or editing consumer mise.toml. Preserve existing RUSTC_WORKSPACE_WRAPPER and clippy-driver nesting; compose any preexisting outer wrapper explicitly rather than overwrite it. [MBX session implementation](https://github.com/jdx/mr-boxington/blob/v1.27.0/crates/mbx/src/session.rs#L579-L639), [transparent dispatch](https://github.com/jdx/mr-boxington/blob/v1.27.0/crates/mbx/src/session.rs#L1739-L1804), [actual child call](https://github.com/jdx/mr-boxington/blob/v1.27.0/crates/mbx/src/session.rs#L1939-L2006).

Its configuration explicitly supports MBX_TARGET_VIEWS, and its own regression covers the value "0" disabling managed targets. Its managed-target documentation specifically directs target-cache users to set MBX_TARGET_VIEWS=0. [1.26 wrapper preservation](https://github.com/jdx/mr-boxington/blob/v1.26.0/crates/mbx/src/session.rs#L579-L588), [1.26 dispatch](https://github.com/jdx/mr-boxington/blob/v1.26.0/crates/mbx/src/session.rs#L1769-L1786), [1.26 forwarding](https://github.com/jdx/mr-boxington/blob/v1.26.0/crates/mbx/src/session.rs#L1928-L1940), [1.26 setting](https://github.com/jdx/mr-boxington/blob/v1.26.0/crates/mbx/src/config.rs#L551-L560), [1.26 boolean regression](https://github.com/jdx/mr-boxington/blob/v1.26.0/crates/mbx/src/config.rs#L2595-L2605), [1.26 target-cache guidance](https://github.com/jdx/mr-boxington/blob/v1.26.0/docs/managed-targets.md#L203-L207). ## 1. Source projection: correctness and authentication

Prefer **in-place restoration into the current actual GITHUB_WORKSPACE**, retaining the current checkout's .git and current execution cwd. This is smaller and more faithful than running a copied workspace with a synthetic GIT_DIR/GIT_WORK_TREE bridge.

1. After ordinary current-source checkout, independently enumerate and authenticate the complete allowed current tracked/declared input inventory. Record actual bytes, type, executable mode and link target. Include tracked configuration, manifests, build scripts, fixtures and declared generated/native inputs required by exact recipes. No cached inventory alone determines what is current.
2. Restore the paired source/target state into a staging area whose archive members are validated. Compare every archived source path against current-source authority before execution.
3. For exactly matching files/subtrees, move the actual restored archived objects into their original checkout locations. Their genuine archived metadata survives. Leave changed/new current checkout objects untouched. Remove cached-only source objects from the candidate projection and reject extra/unbound paths.
4. Preserve whole unchanged subtrees where possible: file-by-file replacement changes parent directory mtimes. Build scripts watching directories, the workspace root, Git metadata, or broad package input sets must be qualified explicitly.
5. Keep the actual current .git untouched and never archive it. Current HEAD/ref/history/dirty-tree semantics remain those of the real checkout. Verify index refresh/untracked behavior for recipes that use Git.
6. Never touch/utime/rewrite source mtimes, invent hash-derived timestamps, restore cached Git metadata, or assert metadata portability across different absolute layouts.

Complete restored state includes both Cargo target-dir and build-dir when distinct. Compatibility binds their actual paths, the checkout root, Cargo source home, toolchain/sysroot paths, native compiler paths and host layout. No concurrent Cargo writers share one lane. Restored registry/git sources and private source archives remain separate from tracked workspace projection and have their own integrity boundaries.

**Dependency coverage versus task identity.** Existing rust/closure.rs derives full task input closures including source_tree, manifests, lock, Cargo config, tests/docs/fixtures, local dependencies, toolchain/platform/features/target/profile/driver and declared extras. Do not use that entire digest as the compiled-state coverage key: it includes application sources and would cause a whole-state generation per application change. Keep it for task/Required identity.

Derive compiler coverage separately from existing resolved Cargo package graph and exact recipes. Include all dependency package manifests/source inputs, lock resolution, features/target/profile, relevant Cargo config, build scripts and declared build/native inputs/environment. A workspace package used as a dependency is included even if it is also a top-level requested package. Application source referenced by a dependency build script is an effective dependency input; changing it must invalidate coverage. Never label every workspace crate an application to improve a reported hit rate. [Current full closure](https://github.com/tailrocks/velnor-new/blob/e851b39e3bedc664f8bd6470c629e7bac36c561c/crates/velnor-actions-rust/src/closure.rs), [blocking-input handling](https://github.com/tailrocks/velnor-new/blob/e851b39e3bedc664f8bd6470c629e7bac36c561c/crates/velnor-actions-rust/src/identity_closure.rs).

An application-only delta can reuse the unchanged generation: reconcile its current source files, run all required exact commands, and do not publish a new full snapshot. The next application revision repeats reconciliation against the same baseline. Unknown outside-tree files, undeclared environment/native inputs, broad directory watchers or unpreserved Git semantics leave the affected recipe unqualified for the zero-work claim. Normal correctness checks still run. Such gaps cannot be silently excluded to declare the task completed.

## 2. Trust and extraction boundaries

Only credential-free compilation/check jobs restore source or compiled state. Signers/publishers never restore or execute compiled cache payloads. Default-branch writer identity must be verified from protected event/ref/workflow context, not cache-key text supplied by source. Explicit read mode applies to PR, merge-group, tag and preview consumers.

The platform review found an important actions/cache boundary: the pinned action invokes tar extraction with -P into GITHUB_WORKSPACE. Its path input helps determine cache version; it does not remap arbitrary archive members or prove containment. A staging directory string alone is not a sandbox. A single prepared payload as the sole action path can let the Velnor helper validate inner members before extracting inner state, but the outer cache extraction still relies on the trusted producer and GitHub cache service scope. No PR-controlled default-scope writer may exist. This is a provenance boundary, not an assertion that action extraction independently rejects traversal.

Do not archive HOME, .git, Cargo credentials, GH/Docker configuration, token-bearing files, arbitrary Mise plugins/shims or private source-fetch sessions. Verify tools through the existing qualified-tool path before using them. Source projection validation must reject unsafe links, traversal, duplicate/colliding entries, foreign roots and unexpected object types before applying the inner projection; preserve the current repository's stricter link policy.

Private sources need a real visibility decision: default-branch GitHub cache visibility to PR readers is not made private by a key prefix. Before caching private Git content or compiled outputs that contain sensitive private material, verify each repository's actual visibility/fork threat model. Retain HD7's fetch/revoke-before-code boundary; token absence alone does not make the fetched bytes safe to expose through a broader cache scope. Velnor main is public and has no configured private_sources; do not infer other repositories' sensitivity from it.

## 3. Grouped execution and writer lifecycle

Retain the three real existing target lanes initially. Combine compatible packages into one workspace/host job, running original package-specific commands sequentially within each lane. Existing native concurrency may run independent lanes only when the resource budget permits. Do not substitute --workspace or merge feature selections, profiles, native flags, targets or toolchains. Every check must execute even if an earlier independent check fails; aggregate failures after all required units, retaining ordinary report behavior.

The final selected lifecycle is workable:

- A trusted read-only combined job validates all required state families before task/compiler side effects.
- If state is complete, that job runs checks and produces the exact selected-unit ledger; no writer runs.
- If incomplete, it reports needs_prepare without pretending checks passed. A conditional writer acquires the one repository writer queue, rechecks state after acquiring it, then runs the same full group recipe set and publishes only after all required producer units succeed.
- PR/read-only events recover locally when cold and never save.
- Required accepts exactly one correctly bound unit ledger from the reader/writer alternatives. Both, neither, wrong attempt/source, unplanned units, missing units, unexpected skip and any task failure remain failures.

The writer holds the shared repository queue for its admission, recheck, save and verification phase, then releases it. Retirement runs separately in a **checkout-free prune job** with narrowly scoped deletion authority; that mutation phase reacquires the same queue and independently rechecks the verified replacement and the complete current inventory before deleting anything. This is a sequence of serialized mutation phases, not one cross-job transaction or a lock held through retirement. All tools/sources/qualification/pruning mutation phases use the same queue. Do not put a parent workflow and its child job under the same held concurrency group. A cold writer may wait; grouped job deadlines must be derived explicitly rather than retaining an accidentally too-small per-crate timeout.

GitHub keys are immutable. A corrupted or partial exact hit cannot be repaired with a same-key save. Use a bounded explicit replacement generation identity and verify replacement availability before retiring the current complete generation. Do not create a fresh key for every app SHA or every consumer run. Account for current state plus replacement overlap plus every other cache family against the decimal byte ceiling. A warning-only save failure never advances current generation.

Current Required is job/crate-oriented, so grouping is not merely renderer formatting: update planned job disposition and per-task coverage bindings together. [crate planning](https://github.com/tailrocks/velnor-new/blob/e851b39e3bedc664f8bd6470c629e7bac36c561c/crates/velnor-actions-orchestrator/src/crate_jobs.rs), [obligation steps](https://github.com/tailrocks/velnor-new/blob/e851b39e3bedc664f8bd6470c629e7bac36c561c/crates/velnor-actions-orchestrator/src/crate_jobs_steps.rs), [Required dispositions](https://github.com/tailrocks/velnor-new/blob/e851b39e3bedc664f8bd6470c629e7bac36c561c/crates/velnor-actions-orchestrator/src/required_dispositions.rs).

## 5. Compiler/native/origin observation

Exact MBX_STATS_REPORT v5 actual-work fields are:

- compiler.miss.invocations and compiler.miss.duration_ns
- compiler.unconsulted.invocations and compiler.unconsulted.duration_ns
- compiler.bypass.invocations and compiler.bypass.duration_ns
- compiler.verification.invocations and compiler.verification.duration_ns

Sum observed invocations across those four outcomes. compiler_invocations_avoided equals hits and is separate. incremental-miss/incremental-unconsulted normalize to miss/unconsulted; incremental_compilations must not be added again. Top-level misses/lookups/unconsulted/bypasses are cache-decision counters and are not substitutes for actual-work counters. The transparent real Rust bypass waits for a compiler child and records bypass; routine Unix compiler probes directly exec and are not counted as real compilations. [report schema](https://github.com/jdx/mr-boxington/blob/v1.27.0/crates/mbx/src/session/stats.rs#L13-L114), [outcome normalization](https://github.com/jdx/mr-boxington/blob/v1.27.0/crates/mbx-cache-core/src/agent.rs#L257-L267), [actual counter update](https://github.com/jdx/mr-boxington/blob/v1.27.0/crates/mbx-cache-core/src/agent.rs#L2532-L2565).

These remain wrapper/session observations. StatsReport v5 does not serialize AgentStats.unit_outcomes; slow_compilations supplies names/durations only. It cannot alone distinguish application compilation from every dependency compilation across recipe/feature/profile/package identity. With current MBX_CC=0 it does not observe native compiler children. Missing/truncated reports or wrappers outside a session cannot mean zero.

Implement observation in existing Velnor, using current dependencies/std and approved executable adapters. The stable adapter records start/finish, original compiler executable/argv, package binding from the current Cargo resolution and invocation environment, target/profile/recipe, process outcome, duration and report integrity. Account for compiler probes separately; preserve @argfile semantics and Clippy wrapper nesting. A successful app compilation must not hide a dependency compilation. For docs/doctests, qualify the corresponding rustdoc/child-compiler boundary rather than assume the rustc wrapper sees every internal invocation. CC/CXX adapters wrap only the declared approved native compilers without changing native flags or discovery. Absolute compiler escapes and silent build-script network HTTP remain explicitly unobserved until qualified; no sum of intercepted events can prove they did not occur.

The current hosted collector already preserves this distinction: scripts/hosted_phase_measurement/report_counters.py keeps fresh_compiler_units, native_cpu, link duration and origin download byte counters null when unavailable. docs/reviews/hosted-phase-measurement-collector.md explicitly refuses to use Compiling lines or MBX lookups as complete totals. Existing local negative-observer harness evidence is not hosted qualification. Do not rename either facility into a complete process/origin monitor.

Current check_runtime.rs::run_check captures bounded child stdout/stderr, verifies success, and returns evidence/container/tools; successful child work is not emitted as ordinary step logs. Publish source/run/job/attempt/recipe-bound observer receipts for successful and failed checks before home cleanup. Preview/native paths must use the same report semantics. A report writer must not turn unobserved work into numeric zero or leak environment credentials.

## 6. Privileged helpers: concrete current blocker

Current SDK publication already has the desired source-free design: fixed rendered data validators, no checkout/local action/project config/candidate execution, exactly admitted data files, pinned gh acquired without source configuration. Move source-derived closure/lock preparation to credential-free production; privileged validation must independently bind it to authenticated workflow/source authority. Do not execute a candidate-built helper merely because that same candidate supplies a checksum. No new tool is needed, but the current source-free image API is absent and must not be invented in the plan. The attempted .velnor/release-manifest.json fetch returned 404; this review has not established a usable current release asset/version pin for this new helper behavior.
